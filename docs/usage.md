# 使用指南与业务规则

Account Manager 用于管理团队共享的单个目标服务账号。管理员负责登记与授权，用户通过领用、反馈和归还维护账号的使用状态。

## 基本流程

1. 管理员创建用户和用户组，在组编辑界面直接添加或移除成员。
2. 批量登记供应商账号，选择同批档位与邮箱取码工具，配置可见用户组或指定用户。
3. 用户在账号大厅选择可用账号，领用后进入“我的领用”查看两段密码。
4. 使用期间反馈额度和异常；结束使用时按正常或异常情况填写归还信息。
5. 归还释放个人领用名额，用户可以继续领用其他账号。

账号情况备注用于记录账号的实际使用情况。备注只允许新增，不能修改或删除；每条备注会显示内容、登记时间和登记人。能看到账号的用户可以查看备注，普通用户只能在“我的领用”为当前领用账号新增备注，管理员可以在账号详情中为任意未删除账号新增备注。

批量导入每行一个账号，使用以下格式；同批账号选择同一档位：

```text
account@example.test----example-password----example-mailbox-password
```

示例均为虚构数据。导入前可预览，确认无格式错误或重复账号后整批提交。同批可统一设置额度重置间隔，后续可逐个编辑；留空沿用系统设置。更改间隔不改变已登记的下次重置时间，只影响后续周期。

“邮箱取码工具”从配置中已注册的工具里单选，默认值由工具配置决定。每个工具组合一个邮箱后端和一个邮件模板；选择“不启用自动取码”则仅保存邮箱密码，验证码需要用户手动获取。管理员也可在账号编辑中单独修改，普通用户不能修改。变更工具或邮箱密码会取消该账号已有取码任务并清除结果，不影响领用状态和账号 2FA。

## 用户和权限

- 本地用户名密码，admin / user；管理员创建用户、初始密码，首次登录及重置密码后强制改密，不开放注册。
- 用户可属于多个组。账号的授权组与指定用户均支持多选，任意匹配即可见；全部为空仅管理员可见。
- 普通用户可领用、反馈、归还。只有当前有效领用者及管理员能读取两段密码、更新额度、上报或清除异常。
- 当前有效领用者及管理员可以主动获取邮箱验证码、获取已配置的账号 2FA 验证码。邮箱取码结果仅发起者可读，管理员也不能读取其他用户的邮箱验证码。
- 账号 2FA 仅由管理员在“账号管理”的账号详情中开启、更新或取消。“我的领用”只提供取码，未配置时显示“未设置”，不提供设置入口。
- 管理员可批量新增与编辑账号、密码、档位、授权、有效期，删除账号、强制回收，维护用户和组、系统设置。保护最后一个管理员。

## 登录密码

新建用户、管理员重置密码、首次登录改密和自行改密统一要求 **15–72 个字符**。支持 Unicode、空格和多个无关词组成的长口令，不强制大小写、数字、符号组合；推荐使用密码管理器生成随机密码。

服务端使用本地 zxcvbn 强度估算，拒绝评分低于 3 的密码，包括常见、重复、顺序和易猜的用户名或姓名组合。密码不会发往外部检查服务。强度估算不能证明密码未泄露或未在其他网站使用，请为本站使用独立密码。这些规则仅适用于本站登录密码，不限制登记的供应商密码和邮箱密码。

管理员重置后，用户下次登录必须改密；密码更新会撤销已有登录会话。升级不会主动重置已有密码，历史密码仍可登录。数据库只保留 Argon2id 哈希，不能从现有哈希确定密码长度或强度；“必须修改初始密码”也不等同于“已确认弱密码”。

登录有按用户名和全站共享的频率限制。出现“登录请求过于频繁”时，请按提示的秒数稍后重试；并发登录也可能短暂触发该提示。已有登录会话不受新登录限流影响。

## 名额与状态

- 账号档位由管理员在系统设置中维护；登记时自动记录启用时间，默认不过期。两类数量上限支持全局默认加单独覆盖。
- 账号同时领用人数只计有效领用；个人领用名额计全部未归还记录，包括回收/删除待确认记录。
- 同一用户同一账号最多一笔未归还记录。归还后允许再领用。
- 账号人数满、本人已经领用、账号过期、个人名额满不可新领用。异常、可能恢复、额度耗尽均允许领用；异常领用需确认提醒。
- 过期、撤销授权或组调整不打断已有领用，原用户仍可查看密码、反馈、归还；禁止无授权的新领用。
- 管理员可停用并恢复账号，停用状态持久化且独立于异常、额度和删除；禁止新领用，已有领用保留并标记已停用，直到用户主动归还。资料、授权、密码和历史均保留，自动额度重置不会恢复启用。
- 管理员回收或删除账号，立即释放账号人数；原用户的“我的领用”仅显示已回收/删除及原因，不能查看账号详情和密码。个人名额直至主动点击归还才释放，不要求再填额度。
- 删除真实用户是例外：自动结束其全部未归还记录并使会话失效。保留审计历史。

## 反馈与计时

- 百分比 0–100；新账号未知。日常可主动更新额度，保存操作人、记录时间、重置时间和来源。
- 剩余额度严格低于耗尽阈值时判为已耗尽，默认阈值5%，管理员可在系统设置调整为1–100%的整数。等于阈值及额度未知不算耗尽；修改阈值不会改变原额度或领用记录。
- 归还只有正常/异常两类。正常归还填写剩余百分比（默认0）和完整的未来重置日期时间；异常归还选择已启用的异常类别或输入问题，至少一项，不强制变更额度。
- 任意状态允许归还。有异常时，正常归还须选择维持或清除异常，默认维持；维持重新开始异常周期。
- 异常冷却结束，或领用异常账号后一直未归还达到观察时长，标为可能恢复；用户主动确认后才标为正常。
- 新异常使旧领用观察计时失效；回收或归还的领用不再触发观察恢复。自动恢复不归还账号或释放名额。
- 重置时间到达，额度自动设为100%，标注系统来源并留下历史，并按账号间隔安排下一次重置；停机期间错过多个周期时只补记一次当前事件，再将下一次时间推进到未来。默认间隔7天，可在系统设置调整为1–365天；批量登记和账号编辑可为单个账号覆盖该值，留空沿用全局设置。健康状态与额度独立。
- 配置默认：账号人数1、个人数量1、观察4h、冷却24h、会话7天、额度重置间隔7天；时间保存UTC，界面北京时间。
- 邮箱验证码默认等待5分钟，管理员可配置1–30分钟，新取码生效；具体操作见[登录验证指南](verification.md)。

## 导入与界面

### 在线配置档位与异常类别

管理员在“系统设置”中新增、改名、停用或删除账号档位和异常类别，无需改代码或重启。配置保存到数据库，重启和备份恢复后保留；服务端保存后即采用新配置，已打开的页面通过每15秒同步或重新聚焦获取更新。

- 初始选项来自 `backend/config/account-options.json`，保留既有档位与异常名称作为默认值。该文件只用于初始化及首次升级；已有系统请通过设置页修改，重启不会覆盖已保存配置。
- 名称与内部标识分离，改名不改变账号所属档位或既有异常关联。每类最多50个选项，名称最多80字；至少保留一个启用档位，异常类别可全部停用或留空，用户仍可填写自由文本。
- 停用档位不能用于新导入或切换档位，原账号继续保留该档位并可编辑其他信息、筛选或正常领用。停用异常类别不能用于新反馈，已有异常与“维持异常”归还继续使用该类别的恢复规则。
- 正被账号引用的选项不能删除（包括已删除账号保留的关联），可改为停用；未被使用的选项可删除。审计记录保留反馈当时的类别名称。
- 每个异常类别可设置1–8760小时的恢复间隔，留空沿用全局默认冷却时长。**多选时取各类别有效间隔的最大值**；只有自由文本时使用全局值，有选中类别时附加描述不参与间隔计算。
- 修改间隔不重置异常起始时间，下次后台检查按新间隔计算仍处于“异常”的账号。现有领用观察规则独立运行：冷却结束或观察达标均可标记为“可能恢复”，不会自动清除异常、归还账号或释放名额。

### 列表与操作

- 每行：账号邮箱----账号密码----邮箱密码。同批一个档位和邮箱取码工具，支持统一授权/有效期/人数上限；忽略空行，兼容LF/CRLF，保留密码字符。预览显示选定工具，修改选项后需要重新预览。
- 先预览，定位错误行、批内重复和已有邮箱（包含删除历史）。有任何错误不允许整批入库，不覆盖旧密码；错误响应和日志不暴露原始密码。
- 大厅清晰显示账号邮箱、档位、额度、独立的下次重置时间、当前领用人和人数、异常和最近额度历史；搜索筛选、不可领原因直观显示。移动端卡片保留下次重置时间，不拼接最近更新摘要。
- 大厅隐藏停用、过期账号，账号管理保留这些条目。五类状态互斥，按异常、可能恢复、额度已耗尽、人数已满、正常的顺序归类；默认全选，支持单选、多选类别合集及全选后取消某类。
- 领用限制展示在操作列按钮下方，个人名额已满优先于人数已满。已有未归还记录不能重复领用；异常和额度耗尽本身不禁止领用。
- 账号大厅默认按剩余额度降序展示，账号管理默认按账号名升序展示。点击当前排序列可切换升降序；切换到账号列时先升序，切换到剩余额度列时先降序，切换到下次重置列时先按近到远。未知额度始终置后，同额度按账号名排序；下次重置未设置的账号在近到远时置前、远到近时置后；移动端提供对应排序选择。
- 桌面表格和移动卡片统一分页，默认每页20个，可选10/20/50/100个；账号总数旁显示每页数量和总页数。搜索、筛选、排序及调整每页数量后回到第一页；先筛选排序再分页。
- 我的领用显示两段密码、单项与整行复制、反馈和归还；回收/删除记录突出主动归还操作。
- 管理概览显示全部账号状态与领用情况；管理账号、用户/组、设置、审计。历史分页。
- 桌面表格、移动卡片；默认每15秒同步。复制功能支持HTTP兼容回退，HTTPS可通过外部反向代理接入。

## 时间与历史

点击时间输入框会展开同一个日期与时间面板，可点选日期并滚动、点选或通过键盘选择小时、分钟，点击“确定”后一起保存；取消或关闭面板会丢弃未确认的修改。界面使用北京时间与24小时制，小时限于00–23、分钟限于00–59，到边界后停止，不循环跳转。

验证码邮件的接收时间按浏览器本地时区显示完整日期、秒及时区偏移，来源为邮箱的实际接收时间，与上述业务时间输入独立。

操作历史记录账号、操作人、目标用户、发生时间和变更内容，已删除对象仍可筛选追溯。供应商密码不写入历史。账号状态来自用户反馈或已登记时间的推算，系统不会自动登录供应商服务检测可用性。

## 可靠性与安全

- REST /api/v1；服务端权限与CSRF；登录密码Argon2id哈希，供应商密码认证加密，密钥以持久secret提供。
- 凭据响应no-store，不写浏览器持久缓存；浏览器检测到会话变化后清空旧页面和凭据缓存，丢弃旧会话的迟到响应。日志、异常、审计不能出现密码。
- 数据库事务控制并发，唯一约束防止重复领用；重复归还/回收不能重复释放名额。变化和历史原子提交。
- 定时任务以持久时间戳和版本为依据，可补处理停机期间事件，不能覆盖较新的用户反馈。
- 初始化不覆盖已有密钥或数据。数据库使用独立持久卷，备份需要同时保留数据库快照与凭据加密密钥。
