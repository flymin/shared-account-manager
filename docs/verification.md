# 邮箱验证码与 2FA

入口位于“我的领用”的账号凭据区域，以及管理员的账号详情。普通用户必须持有当前有效领用；账号被回收、删除或归还后不能继续操作。

## 邮箱验证码

账号邮箱同时作为所选邮箱后端的登录用户名，“邮箱密码”是导入格式中的第三段。管理员在批量登记或账号编辑时选择已安装的邮箱后端插件。内置后端支持其服务提供的不同邮箱后缀；接入其他服务可新增[邮箱插件](mail-plugins.md)。

选择“不启用自动取码”后，领用页显示“未启用自动获取邮箱验证码”，不提供取码按钮。修改后端或邮箱密码会取消旧任务并清除已获取结果，账号密码和账号 2FA 仍可正常使用。后端插件未安装时提示不可用，不会自动切换至其他后端。

1. 在目标服务请求登录代码，点击“获取邮箱验证码”。系统从点击前两分钟起查找未读邮件，并持续等待新邮件。
2. 等待时显示倒计时。默认等待五分钟，管理员可在系统设置调整为 1–30 分钟。
3. 找到第一封符合条件的邮件后停止，显示六位验证码和邮件的实际接收时间，支持复制验证码。该邮件标记为已读。
4. 超时、取消或失败后，可以再次点击，开始新的查找时间窗口。

邮箱后端负责获取邮件，模板插件负责筛选和解析。内置 Template A 同时检查发件人地址和邮件主题，支持不同语言和纯文本、HTML 正文，并仅提取唯一的六位数字代码。规则通过 `MAIL_CODE_SENDER` 和 `MAIL_CODE_SUBJECT_KEYWORD` 配置，未提供界面设置；其他邮件不会被处理。没有已配置模板时不会发起邮箱访问。多个模板匹配同一封邮件时，只有提取结果一致才采用；无法确定唯一验证码或真实接收时间时，不猜测结果。

接收时间显示为完整日期、时间和浏览器所在地的 UTC 偏移，例如 `2026-01-01 08:02:03（UTC+08:00）`。它不是发信时间，也不是本系统读取邮件的时间。

每个账号同时只能有一个取码任务。其他领用者会看到取码人和倒计时，并暂时不能取码；成功结果只向发起者展示。自己的其他页面若遗留任务，可点击“取消已有获取”。

站内切换页面、关闭账号详情会取消本轮；切换标签或应用不会取消。页面关闭时尽力通知服务端，网络异常时由服务端截止时间释放占用。结果最多保留到本轮截止时间，离开页面会清除展示。

## 账号 2FA

账号 2FA 使用 TOTP 验证码。管理员在“账号管理”打开账号详情，点击“上传二维码”，选择目标服务提供的 TOTP 二维码图片来开启本系统的取码功能。支持 PNG、JPEG、WebP，大小不超过 1 MiB、像素不超过 800 万；图片只能包含一个二维码。

只有管理员可在“账号管理”更新二维码或“取消设置”，两种操作均需确认，并影响该账号的所有使用者。取消会清除本系统保存的密钥，领用页同步显示“未设置”并停止刷新。如果其他管理员刚修改配置，需要刷新后重试；无效图片不会覆盖原配置。

“我的领用”仅显示“未设置”或提供“显示”按钮，管理员在此页面也不能设置 2FA。已配置时点击“显示”，显示当前代码及其剩余有效时间，按二维码指定周期自动更新，持续五分钟；再次点击重新计时。站内离开停止显示，切换标签或应用继续计时，返回时校准当前代码。

导入二维码和取消设置仅管理本系统保存的配置，不会在目标服务自动开启、关闭 2FA。首次绑定或关闭两步验证仍需在目标服务完成。

邮箱 2FA 暂时禁用：不提供配置或取码接口，邮箱自动取码仅使用邮箱密码。此前保存的邮箱 2FA 配置保留在数据库中，但不会展示或使用。

## 故障与数据保护

- 提示匹配规则未配置：由管理员按[部署指南](deployment.md#邮箱取码与-2fa)设置发件人地址和主题关键词，并重建应用容器以读取配置。
- 邮箱登录失败：检查邮箱密码；邮箱要求人机验证时，先在其网站完成验证。
- 邮箱要求额外验证：在邮箱网站手动完成验证并查看邮件；当前不支持邮箱 2FA。
- 等待超时：确认目标服务已发送邮件，必要时再次请求登录代码并重新取码。
- 2FA 不匹配：确认二维码属于正确账号和服务，并检查部署主机的时钟同步。
- 邮箱接口变化：当前通过已适配服务的网页邮箱接口访问，供应商页面或接口变更可能需要适配器更新。

二维码原图和邮件正文不落盘。密码、2FA 密钥和短期验证码加密保存；日志、审计、浏览器持久存储不保存这些内容。数据库备份需同时保护凭据加密密钥。取码只在用户主动发起后运行，不是持续的邮箱监控。
