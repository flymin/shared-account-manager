# 查询与分页

## 数据读取约定

列表先在 PostgreSQL 中应用权限、筛选、排序和分页，再按结果 ID 批量加载关联信息。账号详情、领用列表和写入后的响应使用相同的数据组装规则。`app/queries.py` 集中维护这些查询；组装单条响应时不访问数据库。

账号列表一次加载本页的占用人、本人未归还记录、备注数量、授权关系和每个账号最近三条额度记录。最近记录使用一次相关 LATERAL 查询，对每个账号通过额度事件部分索引截取三条，避免读取全部历史后再排名。全局设置及个人名额统计在一次读取过程中复用。用户、用户组、事件和领用使用批量关联读取；概览通过数据库聚合产生统计。

读取批次不跨请求保存，也不能用于写入后的响应。领用等写操作仍持有原有事务锁，并在取得锁后重新检查状态；更新后重新读取统计。密码、授权令牌、2FA 和邮箱验证码不进入列表或共享资源缓存。

## 列表接口

JSON 正文仍为数组，既有字段保持不变。使用 `offset` 和 `limit` 请求当前页，`X-Total-Count` 响应头表示权限范围内、符合筛选条件的总数。即使页码超出结果范围，数组为空时仍返回正确总数。

账号、用户和用户组列表省略 `limit` 时保留完整列表行为；领用接口保留默认每页 100 条的规则。`offset` 从 0 开始，`limit` 为 1–1000。网页的账号列表默认每页 20 条，领用列表每页 50 条。

`GET /api/v1/accounts` 支持：

| 参数 | 含义 |
| --- | --- |
| `scope` | `all` 或 `hall`；大厅额外排除停用、过期账号 |
| `q` | 不区分大小写的邮箱子串，最长 254 字符；`%` 和 `_` 按普通字符匹配 |
| `tier` | 账号类型 ID |
| `group_id` | 授权用户组 ID；不会扩大调用者的可见范围 |
| `statuses` | 逗号分隔的 `disabled,abnormal,possibly_recovered,empty,full,normal` 子集；省略为全部，空字符串为空集 |
| `sort_by` | `email`、`quota` 或 `reset_at`；省略时保留创建时间倒序 |
| `order` | `asc` 或 `desc`，默认 `asc` |
| `offset`、`limit` | 分页范围 |

状态优先级为停用、异常、可能恢复、额度耗尽、人数已满、正常。账号到期独立于该状态，不新增状态类别。个人名额包含待归还记录，账号占用仅统计有效领用；额度耗尽不改变原有领用许可规则。

邮箱采用不区分大小写与重音的自然排序，数字按数值比较。额度未知时始终排在最后；重置时间为空时，升序排在前面、降序排在后面。额度和时间相同时按邮箱自然升序，再以 ID 稳定排序。

例如：

```text
GET /api/v1/accounts?scope=hall&sort_by=quota&order=desc&offset=0&limit=20
GET /api/v1/accounts?statuses=abnormal,empty&limit=20
GET /api/v1/users?offset=0&limit=10
GET /api/v1/groups?offset=0&limit=10
```

用户和用户组列表额外支持 `view=options`，用于编辑器的轻量目录：用户只返回 `id`、`username`、`display_name`，用户组只返回 `id`、`name`。两者仍仅限管理员读取。审计、备注及账号历史保留既有 `before`／`limit` 游标分页。

网页只对当前页做展示格式化。搜索防抖 300 ms；筛选和排序重置页码。资源请求按会话、刷新周期和 URL 合并，失效响应不能覆盖新筛选条件或新身份的数据。15 秒同步周期与验证码生命周期保持原有规则。

## 迁移与索引

迁移 `0014` 增加 `account_email_natural` ICU 排序规则，以及事件、领用分页和 ACL 反向检索的复合索引。被复合索引覆盖的两个单列索引会被替换，降级时恢复；账号、凭据和历史数据不变。

数据库需要支持 ICU 的 PostgreSQL；项目使用的官方 PostgreSQL 镜像包含该支持。迁移应在发布新版应用之前完成。索引创建需要数据库锁，更新前按部署文档备份，在维护窗口执行迁移。

## 回归测试与基准

`tests/test_queries.py` 使用虚构账号验证 SQL 数量不会随列表行数线性增长，同时检查权限、总数、自然排序、空值、最近记录及导入原子性。常用列表的 SELECT 预算包含鉴权，不将墙钟时间作为易受机器负载影响的测试断言。

执行后端测试并准备独立的 `account_manager_test` 数据库后，可以比较当前工作树与某个 Git 版本：

```sh
python3 ops/benchmark_queries.py --reset-test-data --accounts 58 --baseline-ref HEAD
python3 ops/benchmark_queries.py --reset-test-data --accounts 500 --baseline-ref HEAD
```

基准工具会**清空目标测试数据库中的数据**，写入虚构账号，再在只读事务中采样。它拒绝名称不以 `_test` 结尾的数据库。默认通过 Compose 启动临时 API 进程并挂载当前后端源码；也可用 `--runner` 指定已配置到测试数据库的开发容器。不要在并行运行其他测试时重置同一数据库。

`--baseline-ref` 指定要对照的版本；省略时只测当前实现。`--repeat` 默认 5，预热后报告查询次数及处理时间中位数，并在比较时核对新旧响应语义一致。测量包含处理和 JSON 序列化，不包含登录认证、TLS 或外部邮箱调用。密码散列、图片解析、OAuth 和邮箱网络耗时应分别测量。

不同机器的绝对耗时不可直接比较。性能验收以相同环境、相同数据下的改善幅度和固定查询预算为依据；真实环境的诊断记录、身份和地址不进入公共报告或测试夹具。
